# SWEA 1204. 최빈수 구하기

## 문제 유형

- 난이도: D2
- 유형: 카운팅 배열, 빈도수 계산
- 핵심: 점수 범위가 `0~100`으로 작으므로 점수를 배열 인덱스로 사용한다.

## 접근

이 문제는 1000개의 점수 중 가장 많이 나온 점수를 찾는 문제다.

점수 범위가 `0`부터 `100`까지로 고정되어 있으므로 다음과 같은 카운팅 배열을 사용할 수 있다.

```java
int[] count = new int[101];
```

점수를 입력받을 때마다 해당 점수의 등장 횟수를 증가시킨다.

```java
count[score]++;
```

그다음 `0`부터 `100`까지 돌면서 가장 많이 등장한 점수를 찾는다.

```java
for (int score = 0; score <= 100; score++) {
    if (count[score] >= maxCount) {
        maxCount = count[score];
        answer = score;
    }
}
```

## 왜 `>=`를 쓰는가?

문제 조건상 최빈수가 여러 개면 **가장 큰 점수**를 출력해야 한다.

`score`를 작은 점수부터 큰 점수까지 증가시키면서 확인하므로, 빈도수가 같을 때도 갱신하면 더 큰 점수가 답으로 남는다.

예를 들어:

```text
70점 5명
80점 5명
```

이면:

```text
score = 70 -> answer = 70
score = 80 -> count[80] >= maxCount 이므로 answer = 80
```

그래서 `>=`가 맞다.

## 입력 중 바로 갱신할 때 주의점

처음 풀이처럼 입력받는 도중에 바로 갱신할 수도 있다.

```java
count[score]++;
if (maxCount <= count[score]) {
    maxCount = count[score];
    answer = score;
}
```

하지만 이 방식은 같은 빈도일 때 **더 큰 점수**가 아니라 **나중에 등장한 점수**로 바뀔 수 있다.

예를 들어 입력이 다음과 같으면:

```text
80 70
```

둘 다 1번 등장했지만, `<=`로 입력 중 갱신하면 마지막에 나온 `70`이 답이 될 수 있다.

따라서 가장 안전한 방식은:

```text
1. 점수 입력을 모두 세기
2. count 배열을 0부터 100까지 돌며 답 찾기
```

이다.

## Counting Sort와의 관계

이 문제는 정확히 말하면 전체 Counting Sort를 구현하는 문제는 아니다.

Counting Sort의 첫 단계인 **카운팅 배열**만 사용해서 최빈값을 찾는다.

전체 Counting Sort는 보통:

```text
1. 개수 세기
2. 누적합 만들기
3. 정렬 배열에 배치하기
```

까지 하지만, 이 문제는 정렬 결과가 필요 없고 최빈값만 필요하므로 누적합과 정렬 배열은 필요 없다.

## Counting 배열을 쓸 수 있는 조건

카운팅 배열은 데이터 개수보다 **값의 범위**가 중요하다.

| 조건 | 카운팅 배열 사용 |
|---|---|
| 데이터 1000개, 값 범위 0~100 | 좋음 |
| 데이터 100만 개, 값 범위 0~100 | 좋음 |
| 데이터 1000개, 값 범위 0~10억 | 비효율적 |

이 문제는 점수 범위가 `0~100`이라서:

```java
int[] count = new int[101];
```

만으로 충분하다.

## 시간복잡도

점수 1000개를 한 번 세고, 점수 범위 101개를 한 번 확인한다.

```text
O(N + K)
```

여기서:

- `N = 1000`
- `K = 101`

이므로 매우 가볍다.
