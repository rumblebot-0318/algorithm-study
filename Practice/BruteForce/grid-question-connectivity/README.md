# 문자 격자 `?` 채우기

> 완전탐색 + BFS 연결성 검증 연습

`a`, `b`, `c`, `?`로 이루어진 격자에서 모든 `?`를 `a/b/c` 중 하나로 채운다. 완성된 격자에서 **존재하는 각 문자 칸이 각각 하나의 상하좌우 연결 그룹**인 경우의 수를 센다.

## 결정 단위

```text
? 하나에 a / b / c 중 하나를 넣는다.
```

`?`가 `Q`개라면 모든 채우기 조합은 `3^Q`개다. 이 문제는 그 모든 조합을 만들고, 각 결과가 조건을 만족하는지 BFS로 판정한다.

## 상태와 흐름

```text
questionsNodes : ? 좌표 목록
combinations   : 현재 선택한 문자 조합

DFS로 모든 combinations 생성
→ 원본 격자를 deep copy
→ ? 좌표에 조합을 적용
→ a, b, c의 첫 좌표에서 각각 BFS
→ BFS 방문 칸 수 합 == 전체 칸 수면 유효
```

## 왜 `sum == totalSize`인가?

각 문자의 첫 칸에서 BFS를 시작하면, 해당 문자와 연결된 영역 하나만 센다.

- 같은 문자가 여러 덩어리면 첫 덩어리만 세므로 합이 전체 칸 수보다 작다.
- 각 문자가 존재한다면 하나의 연결 그룹일 때만 그 문자 칸이 전부 센다.
- 어떤 문자가 아예 없어도 그 문자는 조건 위반으로 보지 않고 건너뛴다.

따라서 세 문자 BFS의 합이 전체 칸 수와 같으면, 존재하는 모든 문자가 각각 하나의 연결 그룹이다.

## 손추적: `aa?`

`?`는 세 가지로 채울 수 있다.

| 조합 | 완성 격자 | 판정 |
|---|---|---|
| `a` | `aaa` | a 한 그룹 → 가능 |
| `b` | `aab` | a 한 그룹, b 한 그룹 → 가능 |
| `c` | `aac` | a 한 그룹, c 한 그룹 → 가능 |

답은 `3`이다.

## 복잡도

격자 칸 수를 `N`, 물음표 수를 `Q`라고 하면:

```text
시간: O(3^Q × N)
공간: O(N + Q)
```

각 조합마다 격자 복사와 최대 세 번의 BFS를 수행하지만, 문자의 종류는 고정된 3개이므로 한 조합의 비용은 `O(N)`으로 본다.

## 주의점

- 원본 `mapToCharArray`는 모든 조합에서 다시 써야 하므로, 리프마다 `clone()`으로 deep copy한다.
- BFS에서는 큐에 넣는 즉시 `visited` 처리해야 같은 칸이 중복으로 들어가지 않는다.
- 현재 실행 코드는 `?`가 하나 이상 존재한다는 전제다. `?`가 없을 수도 있다면 조합 생성 전에 바로 `groupCheck(mapToCharArray)`를 호출하는 분기를 추가해야 한다.
